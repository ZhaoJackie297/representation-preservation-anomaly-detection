# 为什么 instance-soft 有效，而 temporal-soft 没有独立收益

日期：2026-11-17  
适用范围：当前 CERT r4.2 日粒度用户行为实验  
结论性质：机制解释与可检验条件，不是“任意时序数据都成立”的定理

## 一、先纠正一个容易混淆的比较

SoftCLT 的总目标可以写成：

\[
\mathcal L
=
\lambda\mathcal L_{\mathrm{inst}}
+
(1-\lambda)\mathcal L_{\mathrm{temp}}.
\]

当前实验的五组模型不是同一个变量的简单递增：

| 模型 | instance 项 | temporal 项 | \(\lambda\) | 用途 |
| --- | --- | --- | ---: | --- |
| T0 | hard instance | hard temporal | 0.5 | Native 层级对比参照 |
| T1 | 无 instance 项 | hard temporal | 0.0 | “硬时间对比 + 无实例项” |
| T2 | 无 instance 项 | soft temporal | 0.0 | “软时间对比 + 无实例项” |
| T3 | soft instance | hard temporal | 0.5 | instance-soft 单独效果 |
| T4 | soft instance | soft temporal | 0.5 | 完整 SoftCLT |

因此必须拆成两个比较：

1. `T1 → T2`：固定没有 instance 项，只把 hard temporal 换成 soft temporal；
2. `T3 → T4`：固定 instance-soft，再加入 temporal-soft。

不能用 `T2 vs T0` 直接声称“temporal-soft 有害”，因为那时同时移除了整个跨用户 instance 对比项。

## 二、正样本图视角

对比学习可以看作在表示空间上构造“谁允许靠近、谁必须分开”的图。

### 2.1 instance-soft 的图

对用户 \(u,v\)，先在其 47 维训练期画像上计算数据空间距离 \(d^X_{u,v}\)。SoftCLT 的正权重近似为：

\[
w^I_{u,v}
\approx
\frac{2\alpha}
{1+\exp(\tau_I d^X_{u,v})}.
\]

它有三个几何含义：

1. 行为相似的用户得到较大正权重；
2. 不同但同属正常模式的用户不再被全部当作强负样本；
3. 权重连续衰减，不会把相似用户粗暴合并成一个硬类别。

r4.2 修正版实例权重矩阵的非对角分位数为：1% `0.080`、50% `0.269`、99% `0.446`、最大 `0.500`。这是一个稠密但有梯度的核图，不是少数硬边组成的邻接矩阵。模型学习的是权重的相对排序，而不是把所有正常用户压成同一个点。

标准 instance 对比的目标图中，通常只有同一用户的两个增强视图是正样本，其他用户全部被推向负侧。这在异常稀缺、正常行为类型有限的 CERT 数据上会产生大量“假负例”：

> 两个用户行为相似，仅仅因为用户 ID 不同，就被表示空间强行拉开。

instance-soft 实际修改了正向图的拓扑，而不只是修改损失温度。

### 2.2 temporal-soft 的图

时间软权重只依赖层级序列中的索引距离：

\[
w^T_{t,s}
=
\frac{2}
{1+\exp(\tau_T\,2^d|t-s|)},
\]

其中 \(d\) 是 TS2Vec 的层级池化深度。

它的图具有两个性质：

1. 平移不变：只看 \(|t-s|\)，不看 \(x_t,x_s\) 的内容；
2. 用户内连接：只在同一个用户的相邻时间位置之间加正边。

当 \(\lambda=0\) 时，instance 图被完全删掉，模型只剩“把每个用户相邻日期拉近”的目标。编码器可以退化为用户内的平滑轨迹，而不再要求不同用户的正常模式共享同一表示几何。

两种软权重的信息结构可以概括为：

| 权重 | 是否使用行为内容 | 是否保留时间位置 | 在同一用户内变化 | 在不同用户间变化 |
| --- | --- | --- | --- | --- |
| instance-soft | 是，使用画像距离 | 否，整段训练共用一个用户对权重 | 否 | 是 |
| temporal-soft | 否，只看索引差 | 是 | 是 | 否 |

因此它们不是同一类“软化”。instance-soft 改变的是**谁和谁属于同一正常语义邻域**；temporal-soft 改变的是**同一用户相邻时间点允许拉开多少**。

因此 T2 的根本问题不是“sigmoid 参数不好”，而是：

> temporal-only 目标没有跨用户正边，不能单独恢复正常行为总体的公共流形。

## 三、为什么 instance-soft 能改善表示几何

在局部近似下，带权正样本项等价于图平滑能量：

\[
\mathcal E_I(Z)
\approx
\sum_{u,v}w^I_{u,v}
\left\|z_u-z_v\right\|^2.
\]

完整对比目标还包含负样本排斥和归一化，不能把它完全等同于上式；但正权重决定了哪些点被允许进入同一局部切空间。

instance-soft 把图平滑方向对齐到数据中的行为邻域，因此预期出现三个几何变化：

1. 原始行为空间近邻在表示空间仍为近邻，即 `kNN overlap` 上升；
2. 局部数据距离和表示距离的秩关系更一致，即局部 Spearman 上升；
3. 正常流形不再被大量假负例切碎，有效秩上升，同时语义近邻不会无序散开。

三 seed 机制结果正好符合这三个预测：

| 模型 | 原始邻域 Top-10 一致率 | 局部距离 Spearman | 有效秩 |
| --- | ---: | ---: | ---: |
| T0 | 0.3902 | 0.4401 | 8.884 |
| T1 | 0.2601 | 0.3974 | 5.110 |
| T2 | 0.2149 | 0.4498 | 7.669 |
| T3 instance-soft | **0.4977** | **0.5034** | **14.696** |
| T4 full soft | 0.4952 | 0.4933 | 14.375 |

`T0 → T3` 只改变 instance 项的正样本权重。原始邻域一致率从 `0.390` 上升到 `0.498`，局部距离秩相关从 `0.440` 上升到 `0.503`，有效秩从 `8.88` 上升到 `14.70`。这说明 instance-soft 不是在制造随机高秩噪声，而是同时提高了“与数据邻域一致”和“表示自由度”两个量。

## 四、为什么 temporal-soft 没有独立收益

### 4.1 时间平滑是低通滤波

temporal 图是局部 Toeplitz 图。其平滑能量可写成：

\[
\mathcal E_T(Z)
=
\sum_{u,t,s}w^T_{t,s}
\left\|z_{u,t}-z_{u,s}\right\|^2.
\]

最小化 \(\mathcal E_T\) 会压低用户内的高频差异，保留慢变化轨迹。这相当于沿时间轴做低通滤波。

而当前异常评价主要依赖“某天相对个人历史和跨用户正常模式的偏离”。局部点异常经常正是用户内的高频方向：

\[
r_{u,t}
=
z_{u,t}
-
\operatorname{localmean}(z_{u,t-k:t+k}).
\]

如果训练目标过度压低相邻日期的差异，也会压低这类 \(r_{u,t}\)，使正常与异常的边界变窄。

### 4.2 CERT 的“时间接近”不等于“语义相似”

CERT 的日行为受工作日、岗位、项目阶段、休假和活动稀疏性影响。相邻两个索引日在原始数据中可能对应：

- 正常工作日与正常工作日；
- 正常日在异常起点附近；
- 周末/休假与工作日；
- 补零或低活跃日与正常日；
- 一个持续存在的恶意行为段中的相邻日期。

temporal-soft 只看到索引距离，无法区分这些情况。它不能提供 instance-soft 提供的外部语义信息。

### 4.3 T0 已经有 hard temporal 项

T0 不是纯 instance 模型。它在 \(\lambda=0.5\) 时同时包含 hard instance 和 hard temporal。temporal-soft 做的是“重新加权一个已经存在的 temporal 分支”，没有新增跨用户语义边。

因此：

- 当 \(\lambda>0\) 时，temporal-soft 不能替代 instance 项；
- 当 \(\lambda=0\) 时，它甚至删除了跨用户实例项；
- 它最多只能改变用户内局部平滑强度。

### 4.4 结果分解

`T1 → T2` 说明 temporal-soft 并非完全没有作用：

| 对比 | Δ test PR-AUC | Δ test ROC-AUC | Δ kNN overlap | Δ mean norm |
| --- | ---: | ---: | ---: | ---: |
| T2 - T1 | +0.000756 | +0.012833 | -0.045250 | -1.299063 |

soft temporal 比 hard temporal 略好，但表示平均范数从 `3.271` 降到 `1.972`，跨用户邻域一致率继续下降。也就是说，它让用户内轨迹更平滑、表示更向单位化/低范数方向集中，却没有恢复跨用户的正常结构。

`T3 → T4` 则更直接地隔离了“在 instance-soft 上再加入 temporal-soft”：

| 指标 | T4 - T3 |
| --- | ---: |
| kNN overlap | -0.002533 |
| 局部距离 Spearman | -0.010019 |
| 有效秩 | -0.321008 |
| 平均范数 | -0.023173 |
| validation PR-AUC | -0.000196 |
| test PR-AUC | -0.000055 |
| validation ROC-AUC | -0.001467 |
| test ROC-AUC | -0.000539 |
| test K=10 | 0.000000 |

这些差值很小，不能声称 temporal-soft 有强烈害处；但它们没有形成任何稳定的几何增益。因此更准确的结论是：

> temporal-soft 在当前 CERT 日粒度任务上没有独立增量，并且会轻微稀释 instance-soft 已经建立的局部判别几何。

### 4.5 三 seed 谱实验对上述解释的修正

为了避免停留在文字类比，我进一步在训练好的 T0–T4 表示上计算了两个归一化图 Dirichlet 能量：

\[
R_W(Z)
=
\frac{\operatorname{tr}(Z^\top L_WZ)}
{\operatorname{tr}(Z^\top D_WZ)}.
\]

同时计算了两类“高频残差”的异常检测 AUC：

- instance residual：表示到行为邻域加权中心的距离；
- temporal residual：表示到时间邻域加权中心的距离。

三 seed 结果：

| 模型 | instance Dirichlet | temporal Dirichlet | instance residual ROC | temporal residual ROC | 最终 test PR/ROC |
| --- | ---: | ---: | ---: | ---: | ---: |
| T0 | 0.2937 | 0.2829 | 0.7950 | 0.6071 | 0.007447 / 0.816112 |
| T1 | 0.0936 | 0.4555 | 0.7756 | 0.6325 | 0.005496 / 0.759326 |
| T2 | 0.1265 | 0.3457 | 0.7606 | 0.6966 | 0.006252 / 0.772159 |
| T3 | 0.3456 | 0.2452 | **0.8407** | **0.7651** | **0.008922 / 0.842132** |
| T4 | 0.3352 | **0.2395** | 0.8398 | **0.7717** | 0.008867 / 0.841593 |

三个关键结果：

1. `T1 → T2`：temporal Dirichlet 下降 `0.1098`，temporal residual ROC 上升 `0.0642`，三项种子均为正。因此 temporal-soft **确实执行了低通平滑，也不是完全没有局部作用**。
2. `T3 → T4`：temporal Dirichlet 再下降 `0.00565`，temporal residual ROC 上升 `0.00660`，3/3 seed 同向；但 instance residual ROC 为 1 正 2 负，kNN overlap、有效秩和最终 PR/ROC 均轻微下降。这说明 temporal-soft 的局部时间残差收益没有传递到最终表征库评分。
3. `T3 - T0`：instance Dirichlet 反而增加 `0.0519`，但 instance residual ROC 增加 `0.0458`、temporal residual ROC 增加 `0.1580`，kNN overlap 和有效秩也显著增加。因此不能把 instance-soft 解释成“最小化图能量”或“全局收缩”。更准确的说法是：它重新校准了内容相关的正样本重心，使表示邻域更符合数据语义，而不是把邻域简单压平。

由此需要修正一个理论表述：

> instance-soft 不是单纯的低通平滑算子，而是内容感知的图重新校准；temporal-soft 是时间低通算子，但它的残差可分类性改善不保证最终检测器收益。

## 五、一个统一的几何解释

可以把两种 soft 权重看成两个不同图的拉普拉斯正则：

| 图 | 边 | 主要作用 | 对本任务的风险 |
| --- | --- | --- | --- |
| instance-soft \(G_I\) | 跨用户、由行为画像定义 | 修复假负例，保持正常流形 | 若画像不准，会引入错误邻边 |
| temporal-soft \(G_T\) | 用户内、由时间间隔定义 | 平滑短期轨迹，补充时间连续性 | 会压低点异常的高频方向，且不含跨用户语义 |

instance-soft 的图是**内容相关**的：

```text
行为相似的用户 ── 强边
行为不同的用户 ── 弱边或负边
```

temporal-soft 的图是**内容无关**的：

```text
相邻日期 ── 强边
相隔较远日期 ── 弱边
异常是否发生在相邻日期 —— 权重不知道
```

所以更严格的表述不是“soft temporal 算法本身无效”，而是：

1. 在 \(\lambda=0\) 的 temporal-only 方案中，它不足以替代跨用户 instance 对比；
2. 在 \(\lambda=0.5\) 的 full soft 方案中，它能改善时间高频残差的局部可分性，但没有在 instance-soft 基础上形成端到端收益；
3. 对点异常占主导、行为语义跨越多个用户类别、且时间间隔不携带充分标签信息的 CERT 日粒度任务，时间平滑先验与最终表征库评分方向没有稳定对齐。

## 六、可检验的边界条件

这套解释不是无条件推广。它可以给出三个可证伪预测：

1. 如果异常主要是“孤立点突变”，temporal-soft 应降低点级召回；当前结果是下降；
2. 如果异常主要是“平滑的长期漂移”，temporal-soft 可能有益；这还没有单独验证；
3. 如果用户行为画像能够稳定区分正常行为簇，instance-soft 应同时提高邻域一致率和有效秩；当前三 seed 结果支持该预测。

要真正验证第 2 点，需要构造“点异常 vs 持续缓慢漂移”的合成实验，并保持 instance 项、训练轮数和评价预算不变。当前 CERT 结果只能支持“当前数据分布下 temporal-soft 没有独立收益”，不能支持“temporal-soft 对所有时序任务无效”。
