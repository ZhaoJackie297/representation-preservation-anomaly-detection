# CCF-B 计划勘误 v1.2.2

本勘误替代 v1.2.1 的冲突条文，处理批次共现混杂、A1 版本拆分、pilot 最小正向幅度和支撑集×权重 2×2。

## 1. 研究定位

当前只获准进入 Phase 0 与小型 pilot。

不得提前承诺：

- CCF-B 外部有效性；
- AdaGraph 优于 R0；
- A4 对 A0-official 的任何方法增益；
- 等价性、非劣性已经得到证明。

`D_ext` 未通过数据门禁前，稳妥定位是 CCF-C 上沿；若“批次共现使软实例对比失效，以及如何修复”这一方法学贡献成立，再讨论更高目标。

## 2. B1：共同批次表本身也是治疗

原方案用 `E_A3 ∪ E_A5b` 生成共同批次表，存在两个混杂：

- 批次中包含 A3 图边，对 A3 有信息优势；
- 图上相近的硬负样本更难，A0-matched 可能单纯因批次变难而下降。

### 修订后的联合覆盖

每个 seed、stage 的目标边集合改为：

```text
E_cov = E_A3 union E_A5a union E_A5b
```

三套边必须分别记录：

- `coverage_A3`；
- `coverage_A5a`；
- `coverage_A5b`；
- `active_pair_mass_A3`；
- `active_pair_mass_A5a`；
- `active_pair_mass_A5b`。

每个覆盖率都必须 `>=0.80`。

### 固定 50% 随机填充

batch size 为 16 时：

```text
8 个覆盖设计槽位 + 8 个固定 seed 随机填充槽位
```

规则：

- 设计槽位从尚未覆盖的联合目标边中贪心选择用户；
- 随机填充槽位从同 seed 的固定 `PCG64(seed, stage)` 抽样；
- 填充槽位不得人为偏向 A3、A5a 或 A5b；
- 匹配变体重放完全相同的 16 用户 batch；
- 覆盖率按整个 16 用户 batch 中实际出现的所有目标边计算；
- 如果 50% 填充使 80% 覆盖无法达到，只能增加 `B_stage`、降低 m 或重新设计覆盖算法，不能减少填充比例后声称已控制混杂。

### 预注册分解顺序

每次 pilot 报告都按以下顺序单独呈现：

```text
Step 1: A0-official
Step 2: A0-matched
Step 3: A1-Cov
Step 4: A3 / A4
```

规则：

- 不得把 A4 vs A0-official 写成方法增益；
- A4 vs A0-matched 只表示完整训练分布变化后的总体比较；
- 关系内容和批次共现的分开解释依赖 A1-Cov、A5a、A5b、A3-hard 和 2×2 机制矩阵；
- A0-matched 下降本身不是 AdaGraph 有效证据，只说明共同批次改变了负样本难度。

## 3. B2：拆开 R0 A1 与覆盖版 A1

原 A1 是随机 batch 下的稠密画像软权重。共同覆盖 batch 只保证 A3 稀疏边落批，不等于保证 A1 的稠密边落批。

因此拆成：

### A1-R0

- R0 的完整 A1；
- 原始随机 shuffle；
- 原始稠密画像软权重；
- 单阶段 B；
- 用于保持与已发表/已冻结 R0 方法的可比性。

### A1-Cov

- 固定画像软权重；
- 重放共同覆盖批次表；
- 单阶段 B；
- 用于与 A3/A4 在相同用户对暴露机会下比较。

主因果比较使用 `A1-Cov`。A1-R0 只用于 R0 复现和批次分布差异诊断。

### 重新报告支撑集覆盖

- 每次图更新后，重新生成该 stage 的覆盖目标边；
- 报告新支撑集覆盖率，不得沿用上一 stage 的覆盖率；
- A3 第 2、3 阶段必须有各自的 `coverage_A3`；
- A1-Cov、A1+、A9 重放同一 stage 批次表；
- 如果新支撑集覆盖率低于 80%，A4 不能进入下一阶段，状态记为 `STAGE_COVERAGE_BLOCKED`。

## 4. B3：pilot 的最小正向幅度与种子判据

原先只要均值 `>0` 就算正向，`+0.00001` 也会触发 `FRAGILE_SINGLE_ENDPOINT`，噪声太大。

定义 endpoint 在 pilot 中为正向，必须同时满足幅度和种子方向规则。

### 最小正向幅度

PR-AUC：

```text
Delta_PR >= +0.0005
```

依据与 PR 非劣界同一量级：约为当前 A1 PR-AUC 的 3.55%–6.60%。

K=10 事件召回：

```text
Delta_Recall >= +max(0.02, 1 / N_events)
```

即至少 2 个百分点或一个实际事件步长，取较大者。r4.2 的 24 个事件对应：

```text
1 / 24 = 0.041666...
```

### 种子方向

- 使用 2 个 pilot seed：每个 seed 的同一 endpoint 都必须超过正阈值；
- 使用 1 个 pilot seed：只按幅度判断，并明确标为 `PILOT_ONE_SEED`；
- pilot seed 不用于调参，只用于 Go/Stop；
- pilot 结果不能进入正式 10-seed 统计家族。

### 停止规则

```text
若 (A1-Cov - A0-matched) 在两个主终点上
均未达到上述“正向 endpoint”标准，
则停止 AdaGraph 主实验。
```

只有一个 endpoint 达标：

- 可进入 r4.2 10-seed 方向性复验；
- 标为 `FRAGILE_SINGLE_ENDPOINT`；
- 10-seed 下仍必须满足方向规则和效应区间检查，才能进入 r5.2。

## 5. I2：PR-AUC 非劣的业务可接受损失

在主比较使用 S2 欧氏库时，`-0.0005` PR-AUC 约等于 A1 当前基线的 3.55%–6.60%。

预先定义业务可接受损失：

> 在该固定预算审查系统中，仅当至少一个主终点相对 A7/A8b 获得正向收益时，才接受最多 `0.0005` 的 PR-AUC 损失；同时 K=10 事件召回不得损失超过两个事件。若没有终点收益，则任何超过 0.0005 的 PR-AUC 损失都不接受。

这不是说 AdaGraph 与更强的 A7/A8b 等价，而是规定一个窄的双终点 trade-off 边界。

若最终 `D_ext` 的 A1 PR-AUC 很低，使该绝对界超过可解释的业务差异，必须新建勘误或在外部确认分析中缩小界值。

## 6. I3：训练方差报告

主推断仍为条件于 10 个模型的用户/事件簇 bootstrap。

双层 bootstrap 只作训练随机性敏感性。论文必须写明：

- 它估计“在这些训练运行和用户抽样变化下是否稳定”；
- 它不能自动回答“任取一次训练是否稳定”。

所有主比较必须同时报告：

- 10 个 seed 的逐 seed 配对方向；
- 同号 seed 数，例如 8/10；
- 均值、标准差和配对区间；
- 双层 bootstrap 区间。

8/10 同号是描述性稳健性，不替代 p 值。

## 7. I4：候选排序稳定性

- 12 点候选表固定；
- 20 次训练预算固定；
- 40 次审计必须报告候选排序是否变化，不只看 J 数值；
- 排序稳定性指标：
  - 主选点是否仍在前 3；
  - top-4 集合 Jaccard；
  - Spearman 秩相关；
  - 是否改变各方法之间的排序结论。

## 8. I5：支撑集 × 权重的 2×2 端点

明确写成两个二值因素：

- Support Anchor：支撑集是否使用 `P`；
- Weight Anchor：权重是否使用 `P_m`。

| 单元 | 支撑集 | 权重 | 变体 |
| --- | --- | --- | --- |
| S1,W1 | mixed `P*exp(-d/tau)` | `P_m` | A1-sparse-EMA / `epsilon=0` |
| S1,W0 | mixed `P*exp(-d/tau)` | `exp(-d/tau)` | A3-epsInf |
| S0,W0 | 表示 top-m | `exp(-d/tau)` | A3-noAnchor |
| S0,W1 | 表示 top-m | 在表示支撑集上归一化 `P_m` | A1-repSupport-P |

新增 `A1-repSupport-P` 补齐 2×2。

报告：

- 每行 beta 分布；
- 每行 `P_m` 行熵；
- 每行 `P` 行熵；
- m=5 与 m=10 时是否接近 `ln(m)`；
- KL 实际使用量和可行 beta 比例。

若 `P_m` 近似均匀，画像锚在支撑集内可识别的信息很少，必须明确写出。

## 9. 理论补充：边曝光条件

新增最小理论命题，不依赖不存在的真实假负标签。

### Proposition 1：随机 batch 的边曝光

设：

- 用户数 `N`；
- batch size `b`；
- stage 有 `n_b` 个优化步；
- 每步从用户中无放回均匀选 `b` 个用户。

任意固定无向用户边 `(u,v)` 单步出现概率：

```text
p = b(b-1) / [N(N-1)]
```

stage 内期望曝光次数：

```text
lambda = n_b * b(b-1) / [N(N-1)]
```

至少出现一次的概率：

```text
Pr(exposure >= 1) = 1 - (1-p)^n_b
```

### Corollary：定向覆盖

若覆盖批次表保证一条目标边至少进入 `c` 个 batch，则该边的曝光次数至少为 `c`，因此：

```text
Pr(exposure >= 1) = 1
```

命题只解释“全局软权重为什么会失效”和“覆盖为什么必要”，不证明 AdaGraph 有效。
