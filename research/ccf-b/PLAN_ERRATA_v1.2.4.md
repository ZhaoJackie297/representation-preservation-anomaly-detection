## 1. 结论

可以不再把 ChimeraLog 当作唯一可替代数据集。

新的外部数据优先级：

1. **CLUE-LDS**：真实正常行为 + 官方受控账号劫持注入，最适合本方法的应用级用户行为和图关系；
2. **LANL**：真实企业网络 + 红队事件，适合作真实网络外部压力/确认；
3. ChimeraLog：托管恢复后再考虑；
4. SPEDIA/TWOS：小型压力测试。

这构成两条互补外部证据：

```text
CLUE-LDS: 应用/云行为级，半合成标签
LANL:     真实企业网络，红队标签
```

## 2. CLUE-LDS 已核实信息

数据：

- 名称：Cloud-based User Entity Behavior Analytics Log Data Set；
- DOI：`10.5281/zenodo.7119953`；
- 论文 DOI：`10.1109/BigData55660.2022.10020672`；
- 官方代码：<https://github.com/ait-aecid/clue-lds>；
- 数据许可：CC BY 4.0；
- 代码许可：GPL-3.0；
- 文件：`clue.zip`；
- 压缩大小：635,105,552 bytes；
- 解压后约 14.5 GB。

官方描述：

- 来自 Huemer Group 真实运营的 hBOX/Nextcloud 云存储；
- 约 5,000 个匿名用户；
- 约 5,000 万事件；
- 2017-07-07 至 2022-09-29，共 1,910 天；
- 49 类事件，包括登录、文件访问、编辑、分享、配置变更等；
- 有可选角色字段：consulting、administration、management、sales、technical、external；
- 有文件、组、分享、用户、认证等日志。

官方示例统计：

```text

```

## 3. 标签是怎么来的

CLUE-LDS 原始数据只有正常行为，不包含真实攻击标签。

官方代码通过切换相似用户对模拟账号劫持：

- 计算用户行为相似度；
- 随机选择相似度处于预设区间的用户对；
- 在允许的时间区间选择切换点；
- 在切换点之后交换两个用户的 `uid`；
- 输出 `labels.txt` 记录受影响用户和首次异常时间。

默认参数：

```text
seed=1
num_pairs=10
min_similarity=0.1
max_similarity=0.6
min_days_before_change=25
min_days_after_change=2
min_cnt=100
min_unique_events=4
```

每个 pair 切换两个用户，所以 10 个 pair 产生 20 个受影响的用户级异常。

可以设置：

```text
--pairs 20
```

产生 40 个受影响用户级异常。

## 4. 为什么它比 ChimeraLog 更适合直接替代

优势：

- 可直接下载，不依赖失联网盘；
- 真实用户正常行为，不是完全 LLM 模拟；
- 应用级语义更接近 CERT；
- 有用户、文件、组、分享关系，可构造用户图；
- 有官方、可复现的异常注入代码；
- 用户数和时间跨度充足；
- 可显式控制异常数量、相似度区间和切换时间；
- 能复用现有用户日、固定预算 Top-K、冷却期和证据评价。

限制：

- 标签是受控账号劫持，不是真实恶意内部人员；
- 合成异常依赖相似用户切换，可能与真实攻击分布不同；
- 原始事件只有正常行为；
- 需要防止相似度计算、切换时间和用户过滤导致标签泄漏；
- 角色字段不是所有事件都有，组织图需要从组和分享关系构造；
- 事件数多，预处理需要严格时间切分。

## 5. 建议的 CLUE-LDS 外部协议

### 5.1 数据切分

不要直接使用官方默认跨全时间段的 20 个切换点。

推荐：

1. 先解析用户活跃日和正常事件；
2. 冻结一个训练截止日；
3. 只允许切换时间落入后段评价窗口；
4. 对每个受影响用户保留至少 30 天切换后活跃期；
5. 所有未受影响用户仍可在正常训练期参与表征学习；
6. 冻结后不再根据检测结果移动时间。

建议的起始参数，待 smoke 后冻结：

```text
pairs=20
min_sim=0.1
max_sim=0.6
min_days_before=35
min_days_after=30
seed=20261116
```

附加时间门槛：

```text
最早切换时间 >= 训练截止日 + 1 day
最晚切换时间 <= 数据结束 - 30 days
```

### 5.2 用户日特征

从 49 类事件构造：

- 登录成功/失败；
- 文件创建、读取、修改、删除；
- 分享、取消分享、公开链接；
- 组成员关系变化；
- 配置和管理操作；
- 外部 IP/非本地 IP；
- 活跃时间段；
- unique files/groups/roles；
- 事件类型熵；
- 日事件总量。

不得使用未来事件构造当天特征。

### 5.3 用户图

候选关系：

- 同组共现；
- 文件共享关系；
- 共享目录访问；
- 行为画像近邻；
- 共同外部/内部网络上下文。

所有图只使用训练期构建，并在每个阶段冻结时间范围。

### 5.4 事件单位

以“用户在某切换时刻开始的账号劫持段”为一个事件。

预注册要求：

- 一个 pair 的两个受影响用户是两个独立事件；
- 同一用户只允许一个切换点；
- 事件窗口从 label 首次异常日开始，直到该用户下一次身份切换或数据结束；
- 事件数不足 20 时不报确认性 p 值；
- 目标用 20 pairs 得到约 40 个用户级事件。

## 6. 双外部数据集策略

### D_app：CLUE-LDS

定位：

> 真实正常云行为上的受控账号劫持外部确认。

作用：

- 主要外部应用级证据；
- 可做 PR-AUC、K 事件召回、图关系和证据审计；
- 可比较无图、画像图、AdaGraph 和置换图。

### D_net：LANL

定位：

> 真实企业网络红队事件上的外部压力验证。

作用：

- 真实网络数据和真实红队事件；
- 检验方法跨模态迁移；
- 若无法得到干净时间切分，只报效应和区间，不报确认 p 值。

### B 类条件

建议 B 类外部门槛至少要求：

- CLUE-LDS 通过完整标签、切分和图适配；
- CLUE-LDS 上主比较方向和区间不失败；
- LANL 至少完成可复现外部压力验证且不出现致命反向；
- 不把“半合成账号劫持”写成真实内部人员攻击。

## 7. 与 ChimeraLog 的关系

ChimeraLog 从“主候选”降为“托管恢复后的备选”。

原因：

- CLUE-LDS 已可直接访问；
- CLUE-LDS 使用真实正常用户行为；
- 标签生成代码公开且可控；
- 规模、时间跨度、用户关系和事件数足够。

这比等待失联 OneDrive 链接更可执行。

## 8. 开跑前新增审计

Phase 0 和 pilot 继续按 v1.2.3 执行。并行新增：

1. 下载 CLUE-LDS `clue.zip`；
2. 校验 Zenodo MD5：`9e318370f96b68077667e9cdc05f26a5`；
3. 解压后的 JSON schema；
4. 用户日、角色、组、分享日志规模；
5. 运行一次低采样/小窗口解析，不立即跑全量；
6. 固定异常注入 seed 和时间范围；
7. 检查切换前训练窗口、切换后评价窗口和标签泄漏；
8. 冻结 CLUE-LDS 协议后再进入外部确认。
