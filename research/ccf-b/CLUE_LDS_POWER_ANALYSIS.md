# CLUE-LDS 功效分析

日期：2026-11-18。

## 1. 聚类单位

每次账号劫持注入切换一对用户：

- 一个 pair 生成两个目标用户事件；
- 同 pair 的两个目标共享同一随机切换；
- 因此有效独立单元是 **用户对**，不是 2×pair 个事件；
- 主 bootstrap 必须按 pair 整簇重采样；
- 事件级 bootstrap 只作敏感性。

## 2. 模拟协议

模拟使用：

- 用户对簇数 `K`；
- 每簇 2 个目标事件；
- 每簇共享 latent effect `u_i ~ N(0, sigma^2)`；
- 基线检测概率 `p0`；
- 方法效应写成 log-odds shift；
- 对簇内平均差做单侧 `alpha=0.025` t 检验；
- 目标功效 80%；
- 2,000 次 Monte Carlo；
- 临界值使用标准正态 1.96 近似。

这是设计阶段 MDE，不是实际检测结果。

复现：

```powershell
python clue_lds/power_pair_clusters.py --pairs 24 --repetitions 2000
```

## 3. 当前可实现事件数

在冻结的门禁下：

```text
label_seed=20261101
profile_cutoff=2022-02-28
min_profile_days=20
min_days_before=35
min_days_after=30
switch_window=2022-03-01..2022-08-30
```

CLUE-LDS 最多只能找到 **24 个合格用户对**。

因此正式数据采用：

```text
24 pairs
48 user-level events
```

先前 20 pairs 方案即使可运行，也不应作为最终统计单元。

## 4. 24 对簇的最小可检测效应

80% 功效下，召回率绝对提升的最小可检测效应：

| 基线召回 | 簇 SD 0.5 | 簇 SD 1.0 | 簇 SD 1.5 |
| ---: | ---: | ---: | ---: |
| 10% | 23.37 pp | 25.95 pp | 28.61 pp |
| 25% | 27.21 pp | 28.25 pp | 29.53 pp |
| 50% | 26.31 pp | 24.46 pp | 22.97 pp |

结论：

- 在 24 个有效簇下，只能可靠检出约 **23–30 个百分点**的召回差异；
- 对 5–10 个百分点的小到中等方法增益，CLUE-LDS 外部确认功效明显不足；
- 不能把 Holm 后不显著解释成方法一定无效；
- `D_app` 的主定位应写成“外部效应复验”，不是高功效确认试验。

## 5. 增加簇数的理论上限

如果忽略标签可用性，仅看模拟：

| 用户对簇 | 80% MDE 范围（上述基线/SD 网格） |
| ---: | ---: |
| 20 | 25.4–31.6 pp |
| 24 | 23.0–29.5 pp |
| 40 | 17.6–24.7 pp |
| 60 | 14.4–21.4 pp |
| 100 | 10.9–17.9 pp |

但在当前严格门禁下只有 24 个合格 pair。若要通过扩大事件数提高功效，必须放宽时间窗口、活跃日或相似度约束，这会改变外部有效性，不能直接改写。

## 6. 预先解释规则

- 24 簇下不承诺检出小幅效应；
- 效应接近但统计不显著时，报告效应量和簇 bootstrap 区间；
- “不显著”只表示当前外部数据未能区分方法，不自动表示方法失败；
- 若 CLUE-LDS 的双终点效应区间跨零且实际效应小于 10 pp，应把该数据定位为有限功效的外部压力验证；
- B 类主张必须结合 r5.2、CLUE-LDS、LANL 和机制证据整体判断，不能只看单个 p 值。

CLUE-LDS pilot 的独立停止阈值和双 seed 规则见 `PLAN_ERRATA_v1.2.6.md`；本文件只冻结功效/MDE，不把 MDE 当作方法有效性阈值。
