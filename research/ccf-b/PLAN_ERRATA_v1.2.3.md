# CCF-B 计划勘误 v1.2.3

日期：2026-11-18。

本勘误调整外部数据候选优先级：LANL 取代 SPEDIA/TWOS，成为当前首要外部数据候选，但在标签构念、时间切分和用户图适配通过前，仍不能取代 `D_ext` 确认门禁。

## 1. LANL 已核实事实

官方资源：

- 页面：<https://csr.lanl.gov/data/cyber1/>；
- 数据集 DOI：`10.17021/1179829`；
- 作者：Alexander D. Kent；
- 报告号：LA-UR-15-23810；
- 许可：CC0；
- 数据时间：连续 58 天；
- 数据来源：
  - Windows authentication；
  - process start/end；
  - DNS；
  - network flows；
  - known red-team compromise events；
- 规模：
  - 约 12 GB 压缩；
  - 1,648,275,307 条事件；
  - 12,425 用户；
  - 17,684 台计算机；
  - 62,974 个进程；
- 文件：
  - `auth.txt.gz` 7.2G；
  - `proc.txt.gz` 2.2G；
  - `flows.txt.gz` 1.1G；
  - `dns.txt.gz` 177M；
  - `redteam.txt.gz` 4.8K。

官方下载页需要填写邮箱和使用目的后取得 fence token。当前没有替用户提交联系信息。

## 2. LANL 能取代什么

可以取代：

- SPEDIA 作为首选外部候选；
- TWOS 作为首选外部真实感候选；
- “只依赖 ChimeraLog”作为唯一外部数据路线。

不能直接取代：

- `D_ext` 的完整确认门禁；
- CERT 式“恶意内部人员活动”构念；
- 现成的 47 维画像和用户图协议。

LANL 的真实场景是：

> 真实企业网络中已知红队入侵/凭证滥用事件。

它与 CERT 的内部人员场景有交集，但不完全等价。论文必须写成“真实企业网络红队事件上的外部压力/确认”，不能写成“同类内部威胁场景的独立复现”。

## 3. 必须新建 LANL 适配协议

### 3.1 用户日

- 从 authentication、process、flow、DNS 聚合出用户日特征；
- user/computer 多对多关系不能直接当成单用户机器；
- 明确排除 `$` 机器账号、SYSTEM、Local Service 和纯服务账号；
- 记录过滤前后用户数、事件数和异常损失。

### 3.2 事件单位

`redteam.txt.gz` 提供的是 compromise event，不是完整事件编号。

必须先冻结事件簇规则，例如：

- 同一用户相邻红队事件在固定时间间隔内合并；
- 多用户、同一 source computer 的事件是否视为同一攻击簇；
- 只使用时间与已观测字段，不使用检测结果；
- 事件簇数不足 20 时，不报告确认性 p 值。

### 3.3 时间切分

官方示例红队事件从 `t=151648` 秒附近开始，约等于第 1.75 天。示例不保证是首行，但足以证明不能预设存在 30 天全局干净前缀。

审计顺序：

1. 取得 `redteam.txt.gz`；
2. 完成首事件、末事件、用户数和每日红队事件统计；
3. 若不存在至少 30 天全局干净前缀，禁止使用“全局时间外训练”表述；
4. 可改用预先冻结的“每用户事件前局部基线”，但必须作为新的外部协议，不能冒充和 r4.2/r5.2 相同的切分；
5. 若局部基线也不足，LANL 只作外部压力测试，不进入确认性显著性家族。

### 3.4 用户图

LANL 没有现成 LDAP 部门图。可构造：

- authentication co-access graph；
- shared-computer graph；
- DNS/flow interaction graph。

但这些图与 CERT 的 47 维画像图不是同一输入构念。必须冻结：

- 节点过滤；
- 时间窗；
- 边权；
- 无向化规则；
- 是否用训练期构建；
- 图和标签的时间隔离。

LANL 的外部结论必须写成“对用户关系适配协议的迁移结果”，不能写成同一 `P` 的无修改复现。

## 4. 下载策略

为了控制风险，不直接承诺下载完整 12 GB：

1. 先用官方 fence 获取 `redteam.txt.gz`（4.8K）；
2. 审计时间和事件簇；
3. 若无法做干净时间切分，停止完整下载；
4. 时间切分可行后，再下载 `auth.txt.gz` 和 `dns.txt.gz`；
5. 先跑小窗口 smoke，决定是否需要 2.2G process 和 1.1G flows；
6. 完整下载前冻结文件哈希、过滤规则和特征映射。

## 5. 当前数据优先级

1. LANL：首要真实外部候选；
2. ChimeraLog：若恢复托管，作为跨生成体系候选；
3. SPEDIA：会话级压力测试；
4. TWOS：小样本真实感测试；
5. CERT r1：无标签工程诊断。

## 6. 判定

- LANL 可以取代 SPEDIA/TWOS 的候选优先级；
- LANL 不能自动使论文达到 CCF-B；
- 只有 LANL 的时间切分、事件簇、图适配和许可证全部可审计后，才可进入 `D_ext`；
- 若无法取得至少 20 个可评价事件簇或无有效局部基线，LANL 只作外部压力测试；
- 第三周末仍无合格 `D_ext`，仍按 v1.2.2 的降级规则处理。

## 7. 当前不变项

Phase 0 执行顺序不变：

1. sampler 单测和真实图覆盖；
2. A1-Cov vs A0-matched pilot；
3. 并行 LANL 数据审计；
4. 只有 pilot 和覆盖门禁通过，才跑 10-seed r4.2 与 r5.2 锁定复验。
