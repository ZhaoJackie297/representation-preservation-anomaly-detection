# CCF-B 计划勘误 v1.2.1

日期：2026-11-18。

本勘误替代 v1.2 的冲突条文，重点补齐开跑前的停止规则、A5b 落批覆盖、seed 依赖批次表和 PR-AUC 非劣界依据。

## 1. 新增预注册停止规则：A1 vs A0-matched

在共同覆盖批次门禁通过后，pilot 首先比较：

```text
Delta_PR = PR-AUC(A1) - PR-AUC(A0-matched)
Delta_K10 = Recall@K10(A1) - Recall@K10(A0-matched)
```

两者使用同一 seed、同一批次表、同一编码器和同一评价口径。

停止规则：

> 若 `mean(Delta_PR) <= 0` 且 `mean(Delta_K10) <= 0`，立即停止 AdaGraph 主实验。

解释：

- 这说明固定画像软权重相对“共同批次暴露下的硬实例负样本”没有基础增益；
- 此时不允许继续通过 A3/A4 的图更新寻找偶然赢点；
- 在 R0 论文中必须披露“图边落批和共同批次匹配后，画像软权重没有显示基础增益”的局限；
- 该停止结论只针对当前画像距离和当前评价协议，不证明所有关系学习无效。

若只有一个主终点为正：

- 可以进入 10-seed r4.2 方向性复验；
- 必须标记为 `FRAGILE_SINGLE_ENDPOINT`；
- 不能凭该项直接进入 r5.2 锁定复验；
- 只有 10-seed 下至少一个主终点稳定为正且未违反其他停止条件，才可进入锁定复验。

## 2. A5b 必须在共同批次表下报告实际覆盖

原 v1.2 的共同批次表只以参考 A3/A4 图边为目标，可能导致 A5b 的置换图边大量没有进入梯度。

修订：

```text
E_cov(seed, stage) =
  E_A3(seed, stage) union E_A5b(seed, stage)
```

对每条目标边分别记录：

- `coverage_A3`；
- `coverage_A5b`；
- `active_pair_mass_A3`；
- `active_pair_mass_A5b`；
- 每用户边曝光。

正式要求：

- `coverage_A3 >= 0.80`；
- `coverage_A5b >= 0.80`；
- A5b 没有用户零曝光；
- A5b 必须重放与 A3/A4 完全相同的用户批次表；
- 若 A5b 覆盖不足，A5b 比较状态记为 `INVALID_IMPLEMENTATION`，不能写成“画像锚无信息”或“置换图无差异”。

## 3. 批次表必须随 seed 变化

正式 10 个 seed 不得共享一张全局批次表。

每个 seed 的批次表必须由其自身的：

- 模型初始化；
- 数据顺序；
- A3/A5b 图边；
- `sha256(seed, stage, u, v)` 排序；

共同生成。

完整性检查：

1. 10 个正式 seed 的 `batch_table_sha256` 必须全部唯一；
2. 任意两个 seed 的已落批用户对集合不得完全相同；
3. 报告 10 个 seed 间用户对 Jaccard 的中位数、最小值和最大值；
4. 若两个 seed 的批次表完全相同，该 run 标记为 `INVALID_SEED_RANDOMIZATION`；
5. 不能用 seed 只控制权重初始化、却复用同一 batch 顺序。

若 10 个 seed 的图边本身高度重合，必须如实报告；可以通过 seed 依赖的边排序、覆盖起点和补齐规则仍然生成不同批次表，但不得人为制造无用随机性。

## 4. PR-AUC 绝对非劣界的量级依据

v1.2 的 `delta_margin_PR=-0.0005` 保留，但补充依据。

### 当前 canonical 尺度

从现有项目 canonical 结果可核对的 A1 附近点级 PR-AUC：

| 口径 | PR-AUC 均值 | PR-AUC SD | `0.0005` 相对基线 | `0.0005` / SD |
| --- | ---: | ---: | ---: | ---: |
| r4.2，A1 instance-soft，原 mask 评分 | 0.008922 | 0.000207 | 5.60% | 2.42 |
| r4.2，A1 instance-soft，S2 欧氏库 | 0.014091 | 0.001118 | 3.55% | 0.45 |
| r5.2，当前 S2 欧氏库路径 | 0.007572 | 0.000160 | 6.60% | 3.13 |

解释：

- 在主比较使用 S2 欧氏库时，绝对界相当于 A1 当前 PR-AUC 的约 3.55%–6.60%；
- 相对原 mask 评分，约 5.6%；
- 它不是按极低基线的任意百分比自动变化；
- 它是一个固定绝对量，可在稀有正例 PR-AUC 上保持同一单位；
- `D_ext` 冻结后仍必须重新检查其自身 A1 PR-AUC，若绝对界在该数据上不再具有业务意义，必须新建勘误。

该数值不是“最优超参数”，而是预先声明的非劣容差。

## 5. 更新后的执行顺序

### Phase 0

1. 写 `CommonCoverageBatchSampler`；
2. 单元测试：
   - A3 与 A5b 联合边覆盖；
   - 同 seed 可复现；
   - 不同 seed 批次表不同；
   - 用户不重复；
   - 批次表哈希稳定；
3. 跑覆盖率 smoke run；
4. 通过标准：
   - A3 边覆盖 `>=80%`；
   - A5b 边覆盖 `>=80%`；
   - 没有用户零曝光；
   - 10-seed 表的唯一性测试通过。

未通过不允许离开 Phase 0。

### Pilot

r4.2，1–2 seed：

```text
A0-official
A0-matched
A1
A1-sparse-EMA
A1+
A3
A5a
A5b
A7
```

第一优先比较：

```text
A1 vs A0-matched
```

若两个主终点均无正向效应，执行第 1 节停止规则。

### 并行任务

- 继续审计 ChimeraLog 的替代下载方式；
- 联系作者或检查后续 release；
- 同时核查 LANL/OpTC 的最小可行切片；
- 不因等待外部数据而跳过 Phase 0 和 A1/A0-matched pilot。

### Pilot 通过后

1. 跑 10-seed r4.2；
2. 冻结超参数和批次表生成规则；
3. 在 r5.2 做一次锁定复验；
4. 只有 `D_ext` 通过数据门禁，才进行外部确认。

## 6. 数据不可用的准确说明

“数据没到位”必须拆成三种原因，不能混写。

### 上游链接失效

ChimeraLog：

- 代码和论文公开；
- 官方 GitHub README 明确说明作者毕业后学校 OneDrive 账号受影响；
- 旧数据集下载链接已经不可访问；
- 作者正在寻找新的托管；
- 因此当前不能把 ChimeraLog 视为可直接复现的数据集。

### 数据存在但不适配

SPEDIA：

- Zenodo 可直接下载；
- 本地已下载并核对 MD5；
- 但只有 17 个 `User` 值、25 个活动日期，首日已有异常；
- 因而不能承担 1000 级用户图和至少 30 天干净训练期的确认分析。

### 数据规模不足

TWOS：

- 数据论文和元记录存在；
- 但属于五天受控竞赛；
- 规模不足以支持本项目的主事件召回和 10-seed 图方法确认。

因此当前不是“没有做下载”或“网络慢”，而是：

> 可下载的数据不适配，最适配的新数据上游暂时失联，现有 CERT 独立版本又缺少足够标签。
